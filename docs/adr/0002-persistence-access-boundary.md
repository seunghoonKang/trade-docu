# 영속·접근 경계 — 게스트 단건 / 로그인 거래 건 영속

**비로그인(게스트)** 은 템플릿에서 **단일 문서**를 작성·내보내기만 한다(로컬 draft로 새로고침 보호). **거래 건·선적·잔량·이력·멀티문서 묶음·저장된 거래처/품목**은 **로그인 전용**이다. **로그인 사용자의 거래 건**은 *첫 명시적 저장* 시 서버(Supabase)에 생성되고, 이후 편집은 서버로 자동저장된다. 복원 배너는 *아직 저장 안 한 새 거래 건*에만 뜬다.

## 왜

- 거래 건의 핵심 가치(나중에 CI/PL 추가, 분할선적, 잔량)는 **영속=계정**을 전제한다. 게스트는 서버가 없어 "나중에 이어서"가 불가능하므로 자연히 단건으로 수렴.
- 단계 1의 창립가치 **"가입 없이 즉시 사용"** 은 *단건 작성*으로 유지하고, *시간에 걸친 거래 관리*를 가입의 보상으로 둔다.
- 거래 건을 **첫 저장 시 생성**(즉시 생성 아님)해 빈 껍데기 거래 건이 History를 어지럽히지 않게 한다.
